Waterfall Model

Waterfall Model adalah model pengembangan perangkat lunak yang dilakukan secara berurutan dari satu tahap ke tahap berikutnya. Setiap tahap harus diselesaikan terlebih dahulu sebelum melanjutkan ke tahap selanjutnya. Model ini cocok digunakan ketika kebutuhan sistem sudah jelas sejak awal dan jarang mengalami perubahan.

Tahapan Waterfall Model:

  • Requirement Analysis : Mengumpulkan dan menganalisis kebutuhan sistem.
  • System Design : Merancang struktur sistem, database, dan antarmuka.
  • Implementation : Proses penulisan kode program.
  • Testing : Menguji sistem untuk menemukan kesalahan.
  • Deployment : Sistem mulai digunakan oleh pengguna.
  • Maintenance : Perbaikan dan pengembangan sistem setelah digunakan.

Kelebihan Waterfall:

  • Mudah dipahami dan diterapkan.
  • Dokumentasi lengkap.
  • Cocok untuk proyek dengan kebutuhan yang jelas.

Kekurangan Waterfall:

  • Sulit mengakomodasi perubahan kebutuhan.
  • Kesalahan sering ditemukan pada tahap akhir.

V-Model

V-Model (Verification and Validation Model) merupakan pengembangan dari Waterfall Model yang menambahkan aktivitas pengujian pada setiap tahap pengembangan. Bentuk diagramnya menyerupai huruf "V", di mana sisi kiri berisi proses pengembangan dan sisi kanan berisi proses pengujian.

Tahapan V-Model:

  • Requirement Analysis ↔ Acceptance Testing
  • System Design ↔ System Testing
  • Architecture Design ↔ Integration Testing
  • Module Design ↔ Unit Testing
  • Coding berada di bagian bawah huruf V.

Kelebihan V-Model:

  • Proses testing lebih terstruktur.
  • Kesalahan dapat ditemukan lebih awal.
  • Kualitas perangkat lunak lebih baik.

Kekurangan V-Model:

  • Kurang fleksibel terhadap perubahan kebutuhan.
  • Memerlukan dokumentasi yang cukup banyak.

Simple Interaction Design Model

Simple Interaction Design Model adalah model perancangan antarmuka pengguna (User Interface) yang berfokus pada kebutuhan dan pengalaman pengguna. Model ini bersifat iteratif sehingga proses desain dapat diperbaiki berulang kali berdasarkan hasil evaluasi.

Tahapan Simple Interaction Design Model:

  • Identify Needs : Mengidentifikasi kebutuhan pengguna.
  • Develop Alternative Designs : Membuat beberapa alternatif desain.
  • Build Interactive Versions : Membuat prototipe atau desain interaktif.
  • Evaluate : Menguji dan mengevaluasi desain dengan pengguna.

Model ini sering digunakan dalam pengembangan aplikasi web dan mobile karena berfokus pada kenyamanan pengguna saat menggunakan sistem.

Star Lifecycle Design Model

Star Lifecycle Design Model adalah model pengembangan antarmuka yang menempatkan proses evaluasi sebagai pusat dari seluruh aktivitas desain. Setiap tahap dapat langsung menuju evaluasi tanpa harus mengikuti urutan tertentu.

Tahapan Star Lifecycle Design Model:

  • Task Analysis : Menganalisis tugas dan kebutuhan pengguna.
  • Requirements Specification : Menentukan kebutuhan sistem.
  • Conceptual Design : Membuat konsep desain.
  • Prototyping : Membuat prototipe.
  • Implementation : Mengembangkan sistem.
  • Evaluation : Mengevaluasi setiap tahap pengembangan.

Kelebihan Star Lifecycle Design Model:

  • Sangat berorientasi pada pengguna.
  • Evaluasi dilakukan secara terus-menerus.
  • Membantu menghasilkan antarmuka yang lebih baik.

Kekurangan Star Lifecycle Design Model:

  • Memerlukan waktu evaluasi yang cukup lama.
  • Dapat meningkatkan biaya pengembangan.
